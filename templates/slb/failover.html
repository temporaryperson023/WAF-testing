Haltdos Failover Configuration
01
Health Monitor Must Be Active
Failover only works if a health monitor is configured. Without it, Haltdos cannot detect that a server is down. Use /slb/health/probe as the monitor endpoint.
02
Set Unhealthy Threshold
In Haltdos set Unhealthy Threshold = 3 — server is marked down only after 3 consecutive failed probes. Prevents false positives from brief network hiccups.
03
Set Healthy Threshold
Set Healthy Threshold = 2 — server is added back to the pool only after 2 consecutive successful probes. Prevents flapping (server going up and down repeatedly).
✓
Automatic Failover Active
Haltdos now handles failures automatically — no manual intervention needed when a backend server goes down

⚠️ What Happens if ALL Servers Go Down?
!
Zero healthy servers in pool
All backends are down — Haltdos has nowhere to route traffic
02
Haltdos returns 502 / 503
Users see a 502 Bad Gateway or 503 Service Unavailable — Haltdos itself is still up, but no backend can serve the request
✓
Custom error page kicks in
Configure a custom error page in Haltdos so users see a friendly message instead of a raw error code
Haltdos tip — Always configure at least 2 servers in your pool for high availability. One server going down should never cause an outage — the other server absorbs the traffic automatically.
