SLB Module 01 Haltdos ADC — Health Monitor

Health Monitor

Haltdos SLB probes this endpoint before routing any traffic to this backend. If the probe returns 200 OK, the server is marked healthy and receives traffic. If it fails, Haltdos removes it from the active pool until it recovers.

Probe Endpoint
GET /slb/health/probe

This is the URL you configure inside Haltdos as the health check target. Click below to fire a probe request right now and see the raw response.

Haltdos Configuration
01
Open Haltdos Console
Go to ADC → Listeners → Your Listener → Server Groups
02
Add a Health Monitor
Click Monitors → Add Monitor and set type to HTTP
03
Set the Probe URL
Set path to /slb/health/probe and expected response code to 200
04
Set Intervals
Recommended: interval 10s, timeout 5s, healthy threshold 2, unhealthy threshold 3
✓
Backend is now monitored
Haltdos will probe every 10 seconds and route traffic only when this endpoint responds with 200 OK

timestamp unix time When the probe was answered — Haltdos logs this
Haltdos Monitor Types
HTTP / HTTPS — Sends a GET request and checks the status code. This is what we use here.
TCP — Just checks if the port is open. No HTTP needed.
SSL Hello — Checks if the server responds to a TLS handshake.
SMTP / POP — For mail server backends.
Custom Script — Run your own shell script as a health check. Most flexible option.
Why this matters — If your backend goes down and there is no health monitor configured, Haltdos keeps sending traffic to it and users get errors. With a monitor configured, Haltdos detects the failure within seconds and automatically stops sending traffic until the server recovers.
