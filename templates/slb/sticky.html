SLB Module 03 Haltdos ADC — Session Persistence

Sticky Sessions

Once your first request is assigned to a backend server, all subsequent requests from your browser are pinned to that same server via a session cookie. Clear the session to simulate a new client being assigned fresh.

Session Actions

Click Send Request multiple times — you will always land on the same server. Then click Clear Session to simulate a new client and get reassigned.

How It Works
01
First Request Arrives
No session cookie present — Haltdos picks a server using the configured LB algorithm (e.g. Round Robin)
02
Session Cookie Set
Haltdos sets a session cookie in the response that maps this client to the assigned server
03
All Future Requests Pinned
Browser sends the cookie automatically — Haltdos reads it and always routes to the same backend server
✓
Session Persistence Active
User's data stays on one server — no lost cart, no re-login, no broken state across requests
Haltdos Configuration
Go to ADC → Listeners → Server Groups → Persistence
Set Persistence Type to Cookie or Source IP
Set Timeout — how long a session stays pinned before expiring
If the pinned server goes down, Haltdos reassigns the client to a healthy server automatically

What Happens if Pinned Server Goes Down?
!
Pinned server becomes unhealthy
Health monitor detects failure — server removed from pool
02
Haltdos detects broken pin
The session cookie now points to a server that is unavailable
✓
Client reassigned automatically
Haltdos picks a new healthy server and updates the session pin — user may need to re-login but does not get an error page
Haltdos tip — Cookie-based persistence is more reliable than IP-based because multiple users can share the same IP (e.g. behind NAT). Use Source IP persistence only when clients cannot accept cookies.
