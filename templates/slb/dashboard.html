Haltdos ADC / SLB

Server Load Balancer Lab

A dedicated testing environment for Haltdos SLB features — health monitors, load balancing algorithms, sticky sessions, and failover simulation. Each module isolates one SLB behaviour so you can configure and verify Haltdos ADC rules with precision.

01 Monitor
Health Monitor
A dedicated probe endpoint that Haltdos health monitors can target. Returns 200 OK with a JSON status payload. Used to mark backends as healthy before traffic is routed to them.
/slb/health ↗
02 Algorithm
LB Algorithm
Simulate five Haltdos load balancing algorithms — Round Robin, Least Connections, IP Hash, Weighted, and Random. See in real time which server gets selected and exactly why.
/slb/lb-algo ↗
03 Session
Sticky Sessions
Tests Haltdos session persistence — once a client is pinned to a backend server, all subsequent requests from that client go to the same server. Clear the session cookie to test re-assignment.
/slb/sticky ↗
04 Failover
Failover Simulator
Manually take servers up or down to simulate backend failures. Verify that Haltdos correctly removes unhealthy servers from the pool and redistributes traffic to remaining healthy ones.
/slb/failover ↗
05 Identity
Server Identity
Reveals which backend server in the pool served your request — server ID, IP, zone, and client details. Useful for verifying that Haltdos is distributing traffic across the correct servers.
/slb/server-info ↗
How to use this lab with Haltdos — Deploy this app as a backend server in your Haltdos ADC listener. Add /slb/health/probe as the health monitor URL. Then use each module to test and verify the SLB behaviour you have configured in the Haltdos console.
